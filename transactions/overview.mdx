The Transactions API allows you to create and manage payments using multiple methods: PIX (Brazilian Real), USDT (Tether), and BTC (Bitcoin). All methods support idempotency to prevent duplicates and return QR Codes for processing.

## What are Transactions?

Transactions represent payment operations in the Monkei system. Each transaction can be a payment (incoming money) or a withdrawal (outgoing money). Payments generate QR codes that customers can scan to complete the transaction.

<Note>
  All payment endpoints require API Key authentication (via `X-API-Key` header) and implement idempotency through the `idempotency_key` field.
</Note>

## Transaction Flow

<Steps>
  <Step title="Create Payment">
    Create a payment transaction using one of the payment methods (<a href="/transactions/pix">PIX</a>, <a href="/transactions/usdt">USDT</a>, or <a href="/transactions/btc">BTC</a>).
  </Step>
  <Step title="Get QR Code">
    Receive a QR code that your customer can scan to complete the payment.
  </Step>
  <Step title="Monitor Status">
    Use <a href="/transactions/check-status">Check Status</a> to monitor the transaction status or configure webhooks for real-time updates.
  </Step>
  <Step title="Payment Confirmed">
    Once the payment is confirmed, you'll receive a webhook notification and the transaction status will update to `COMPLETED`.
  </Step>
</Steps>

## Transaction Statuses

| Status | Description |
|--------|-------------|
| `PENDING` | Transaction created, awaiting payment |
| `COMPLETED` | Payment confirmed and completed |
| `FAILED` | Payment failed |
| `EXPIRED` | Transaction expired |
| `CANCELED` | Transaction was canceled |
| `BLOCKED` | Transaction is blocked |

## Key Features

- **Idempotency**: Prevent duplicate transactions using `idempotency_key`
- **QR Codes**: Automatic QR code generation for all payment methods
- **Real-time Updates**: Webhook notifications for status changes
- **Multiple Currencies**: Support for BRL (PIX) and USD (crypto)
- **Expiration Control**: Set expiration times for payment requests

## Use Cases

- **E-commerce**: Accept payments for online purchases
- **Marketplace**: Process payments between buyers and sellers
- **SaaS**: Collect subscription payments
- **Donations**: Accept donations via multiple payment methods
