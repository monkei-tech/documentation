Webhooks allow your application to receive real-time notifications about events happening in your Monkei account, such as when a payment is confirmed.

## Configuring Webhooks

<Steps>
  <Step title="Access Integrations Section">
    In the dashboard, navigate to **Integrations > Webhooks**.
    
    ![Webhooks Dashboard](/images/webhook_start.png)
  </Step>
  <Step title="Create New Webhook">
    Click on **"New Webhook"**. Enter the URL of your application that will receive the events (e.g., `https://api.yoursite.com/webhooks/monkei`) and select the events you want to listen to.
    
    ![Create Webhook Modal](/images/webhook_modal.png)
  </Step>
  <Step title="Save and Activate">
    Save your webhook. It will be active and ready to send events to your URL.
    
    ![Webhook Created](/images/webhook_created.png)
  </Step>
</Steps>

## Supported Events

Monkei supports the following webhook events:

| Event | Description |
|-------|-------------|
| `payment.completed` | Triggered when a payment (PIX or Crypto) is successfully received and confirmed. |
| `payment.pending` | Triggered when a payment is created and waiting for confirmation. |
| `payment.failed` | Triggered when a payment fails. |
| `payment.expired` | Triggered when a payment expires without being completed. |
| `withdrawal.completed` | Triggered when a withdrawal is successfully processed. |
| `withdrawal.pending` | Triggered when a withdrawal is created and waiting for processing. |
| `withdrawal.failed` | Triggered when a withdrawal fails. |

## Webhook Delivery & Retry System

Monkei implements a robust retry mechanism to ensure your webhooks are delivered successfully.

### Delivery Attempts

Each webhook delivery has a maximum of **5 retry attempts**. If a webhook fails to be delivered, Monkei will automatically retry with the following schedule:

| Attempt | Delay | Total Time Since First Attempt |
|---------|-------|--------------------------------|
| 1st retry | 30 seconds | 30 seconds |
| 2nd retry | 60 seconds | 1.5 minutes |
| 3rd retry | 5 minutes | 6.5 minutes |
| 4th retry | 30 minutes | 36.5 minutes |
| 5th retry | 1 hour | 1 hour 36.5 minutes |

After 5 failed attempts, the webhook delivery will be marked as `FAILED` and no further retries will be attempted.

### Delivery Status

Webhook deliveries can have the following statuses:

- **PENDING**: Initial state, waiting to be sent
- **RETRYING**: Delivery failed and is scheduled for retry
- **DELIVERED**: Successfully delivered to your endpoint
- **FAILED**: All retry attempts exhausted, delivery failed

### Best Practices

1. **Respond quickly**: Your endpoint should respond within 10 seconds to avoid timeouts
2. **Return 2xx status codes**: Return `200 OK` or `201 Created` to indicate successful processing
3. **Idempotency**: Implement idempotency checks using the event ID to handle duplicate deliveries
4. **Logging**: Log all webhook deliveries for debugging and auditing purposes
5. **Monitor failures**: Set up alerts for failed webhook deliveries to ensure you don't miss important events

## Verifying Signatures

To ensure the webhook request comes from Monkei, verify the signature header `X-Monkei-Signature`.

The signature is generated using HMAC-SHA256 with your webhook secret. Always verify the signature before processing the webhook payload.

```javascript
const crypto = require('crypto');

function verifySignature(payload, signature, secret) {
  const hash = crypto
    .createHmac('sha256', secret)
    .update(payload)
    .digest('hex');
    
  return hash === signature;
}

// Usage example
app.post('/webhooks/monkei', express.raw({ type: 'application/json' }), (req, res) => {
  const signature = req.headers['x-monkei-signature'];
  const payload = req.body;
  
  if (!verifySignature(payload, signature, process.env.WEBHOOK_SECRET)) {
    return res.status(401).send('Invalid signature');
  }
  
  const event = JSON.parse(payload);
  // Process the event...
  
  res.status(200).send('OK');
});
```

## Webhook Payload Structure

All webhook payloads follow a consistent structure. The `amount`, `fee`, and `remaining_amount` fields are integers representing the value in the smallest unit based on the payment method:

- **PIX (fiat)**: Amount in cents (e.g., `5000` = R$ 50,00)
- **USDT**: Amount in smallest unit with 6 decimals (e.g., `1000000` = 1.000000 USDT)
- **BTC**: Amount in satoshis with 8 decimals (e.g., `2072` = 0.00002072 BTC)

```json
        }
```

```json
    "devMode": false
}
```

### Payload Fields

- **id**: Unique identifier for the event (transaction ID or billing ID)
- **event**: Event type in the format `{type}.{status}` (e.g., `payment.completed`, `withdrawal.failed`)
- **data**: Event-specific data object containing the relevant information (transaction or billing data)
- **devMode**: (Optional) Boolean flag indicating if the webhook was sent in development mode

### Transaction Fields

- **id**: Transaction UUID
- **amount**: Integer value in smallest unit (cents for PIX, satoshis for BTC, smallest unit for USDT)
- **fee**: Integer value in smallest unit representing the platform fee
- **remaining_amount**: Integer value in smallest unit representing any remaining amount
- **method**: Payment method (`PIX`, `BTC`, `USDT`)
- **status**: Transaction status (`PENDING`, `COMPLETED`, `FAILED`, `EXPIRED`)
- **type**: Transaction type (`PAYMENT`, `WITHDRAWAL`)
- **currency**: Currency code (`BRL`, `USD`)
- **status_paid**: Crypto payment state (`FULL_PAID`, `PARTIAL_PAID`, `OVERPAID_PAID`, or `null`)
- **hash**: Blockchain transaction hash (if applicable)
- **request_id**: Client-side identification ID used for idempotency

## Monitoring Webhook Deliveries

You can monitor the status of your webhook deliveries through the Monkei dashboard:

1. Navigate to **Integrations > Webhooks**
2. Click on a webhook to view its details
3. Check the **Deliveries** tab to see all delivery attempts, including:
   - Delivery status
   - HTTP response codes
   - Response times
   - Error messages (if any)
   - Retry schedules

This allows you to debug issues and ensure your webhooks are being delivered successfully.
